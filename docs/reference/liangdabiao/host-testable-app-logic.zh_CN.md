# 把应用逻辑留在主机上

为[三字经儿童学习游戏](sanzijing-kids-game/README.zh_CN.md)而写。这个应用代码约 3800 行，包含一套能完整玩的闯关、错题重练、解锁规则和一个带版本号的存档格式——其中大约 600 行逻辑（外加 410 行生成的经文表）是在电脑上跑、在电脑上测的，**不接板子**。

## 让这一切成立的那条分界

应用里有两类模块，分界只有一条规则：**纯逻辑模块不得包含 `esp_*.h`、`lvgl.h`、`nvs.h`、`freertos/*` 或任何平台头文件。** 它只接收普通 C 类型、只返回普通 C 值、不持有任何硬件状态。

| 纯逻辑（主机测试） | 绑硬件（只能在设备上验） |
| --- | --- |
| 经文取句辅助函数 | 四个界面页面 |
| 出题与判分 | 按键分发与页面跳转 |
| 练习会话状态机 | NVS 读写 |
| 星星、错题位图、序列化 | 音效播放 |

回报不只是"有测试更好"，而是**整个规则层可以在你正在打字的这台机器上，用毫秒级的时间跑穷举**：

```bash
cc -std=c11 -Wall -Wextra -Werror -I main \
   tests/test_szj_quiz.c main/szj_quiz.c main/szj_text_util.c main/szj_text.c \
   -o test_szj_quiz && ./test_szj_quiz
```

## 让每个入口都守一个承诺

一个返回 `bool` 的模块，只有把**失败时的行为**写清楚才可测。这里通行的规则是：**失败时不许动输出。** 这样调用方永远不必去检查一个被写了一半的结构体，测试也能直接断言这条承诺，而不只是看返回值。

```c
assert(!szj_stanza_text(0, text, 8));    // 缓冲区太小
assert(text[0] == '\0');                 // ...而且输出已被清空
```

对非法下标和空指针同样如此——要**显式断言**，而不是当成"应该不会发生"：

```c
assert(szj_progress_total_stars(NULL) == 0);
assert(!szj_progress_is_wrong(NULL, 0));
assert(!szj_quiz_build(0, -1, NULL));
```

这些很容易被跳过。被主机测试断言过的 `NULL` 检查，你知道它存在；只在脑子里推演过的那个，恰恰会从真正被走到的那条路径上漏掉。

## 确定性是设计要求，不是锦上添花

出题时的干扰项是伪随机挑的，但种子只取决于 `(课号, 题号)`：

```c
static uint32_t question_seed(int lesson, int question) {
    return (uint32_t)(lesson * SZJ_QUESTIONS_PER_LESSON + question) * 2654435761u + 12345u;
}
```

这一个决定换来三件事：

- 测试可以断言**精确内容**——第 2 课第 7 题每次跑都是同样三个选项，所以失败是可复现的，而不是"它挂过一次"。
- 错题重练能只凭一个句号重建出那道题，不需要存任何题目数据。
- "随机"依然诚实：在人的眼里选项仍然分布得没有规律，而在测试眼里代码是完全确定的。

## 全量扫，不要抽样

主机测试便宜到可以每个情况都验，而不只是挑代表：

- 全部 **404 句**：非空，且正好 9 个 UTF-8 字节。
- 全部 **101 课**：拼出来的整课文本正好 36 字节，且装得进 64 字节缓冲区。
- 全部 **101 × 3 = 303 道题**：答案是题面的下一句；三个选项都在范围内且文案两两不同；没有一个是题面；`correct_slot` 确实指向答案。
- 全部 **403 对相邻句**，验证"相邻两句文案不得相同"。

最后一条值得多讲一句。重复句**不是代码 bug**，而是数据 bug——它会造出**一道有两个正确答案的题**，而在设备上，它会表现为几个月后在第六十几课某处冒出一道莫名其妙的题。把它写成针对生成数组的主机测试，就是一个五行循环。

## 要测数据和常量，不只是测函数

有两类断言抓到的问题，靠读代码是发现不了的：

**生成数据的结构性不变量。**

```c
assert(SZJ_LINE_COUNT % SZJ_LINES_PER_STANZA == 0);
assert(SZJ_STANZA_COUNT * SZJ_LINES_PER_STANZA == SZJ_LINE_COUNT);
```

如果将来经文行数长到不是 4 的倍数，最后一课就会被截断，而界面会静默地把它分错课。这两行把这个情况变成一次构建失败。

**派生常量之间的自洽。**

```c
assert(SZJ_PROGRESS_BLOB_SIZE ==
       SZJ_PROGRESS_HEADER_BYTES + SZJ_LESSON_COUNT + SZJ_WRONG_BYTES + 1);
assert(SZJ_WRONG_BYTES == (SZJ_LINE_COUNT + 7) / 8);
```

这些常量决定存档里到底写几个字节。写错一个，存档就短一个字节；校验和会在加载时抓到它，但那是在设备上、而且是在一次断电之后。

## 存档格式要往返测，还要"虐待"它

序列化值得比"顺利路径"更多的测试，因为这些数据要穿过一次断电和一颗 Flash 控制器：

```c
assert(szj_progress_deserialize(&back, blob, size));       // 往返
assert(back.card_line == 42);
assert(back.stars[7] == 2);
assert(szj_progress_is_wrong(&back, 11));

assert(!szj_progress_deserialize(&back, bad, sizeof(bad) - 1));   // 截断
```

把魔术字节、版本号、长度、校验和**逐个**改坏，每一次都断言被拒绝。一个拒绝不了的格式，就是一个会在最糟糕的时刻被"应用一半"的格式。

## 语义规则也属于纯逻辑层

凡是玩家会感知为"这游戏行为怪怪的"的东西，都是规则；而规则要放在能被测的地方：

```c
szj_progress_record_lesson(&p, 0, 2);
szj_progress_record_lesson(&p, 0, 1);
assert(p.stars[0] == 2);        // 星星只增不减,重练也一样
```

这就是"重练不会让你掉星"这条规则，两行断言。要在真机上靠玩游戏发现它，得有一位极有耐心的测试者。

## 不要试图拿去测界面的部分

别把这套模式硬套到界面上。版式、控件生命周期、按键时序和 NVS，需要真机，或者需要仓库里那套基于桩的 demo 运行时测试。目标是把"**只能**在硬件上验"的范围缩小，而不是消灭它——上面这层纯逻辑覆盖了规则、解锁与存档格式，把 LVGL 那层留给真机。

## 这套做法当场抓到的一个缺陷

`szj_quiz.c` 用了 `uint32_t` 却没有 include `<stdint.h>`。它在 ESP-IDF 构建里恰好能编过，因为有别的头文件间接把类型引进来了。而为了主机测试单独编译它、又开着 `-Werror` 时，第一次就报错。这就是整套做法的通用论据：**对纯逻辑层而言，主机测试是一个严苛得多、也快得多的编译器**，而且它跑在动辄几分钟的固件构建之前。

## 检查清单

- 纯逻辑模块不含平台头文件；这条分界写在每个模块顶部的注释里。
- 每个入口都写明并落实"失败时不动输出"。
- 非法下标与空指针是断言过的，不是假设的。
- 随机性由稳定输入确定性地播种。
- 循环覆盖每一课、每一题、每一句，而不是抽样。
- 数据形状的不变量（倍数关系、字节宽度、无相邻重复）与派生常量都有断言。
- 存档格式测了"被拒绝"，不只是测了往返。
- 玩家可见的游戏规则都在纯逻辑层有断言。
- 每个测试都接进了 `tools/validate.sh --static`，所以 CI 和本地都会自动跑到，不依赖谁记得手动执行。
