# 把应用逻辑留在主机上

为[侨批填字问答](qiaopi-quiz/README.md)而写：一个把网页问答搬到三键手持机上的移植。
固件大约 1900 行界面与服务代码，但真正做决定的那部分 —— 一局怎么抽题、怎么判分、
文本怎么折行、音频怎么解码、进度怎么存 —— 是约 890 行手写加 1333 行生成代码，
它们完全不碰 ESP-IDF 与 LVGL，在开发机上编译运行，对着 1658 行测试，不接板子。

好处不是理念上的。好处是：一个计分 bug 的验证从一次刷机变成一个两秒的测试运行；
而且好几个真缺陷在第一次刷机之前就被找出来了。

## 分界线画在哪

纯逻辑，因此可在主机上测：

| 模块 | 行数 | 职责 |
| --- | --- | --- |
| `qpq_session` | 233 | 单局状态机、计分、连对加成、抽题 |
| `qpq_progress` | 155 | 存档格式、已见题位图、拒绝路径 |
| `qpq_wrap` | 157 | 按字数预算做的 UTF-8 折行 |
| `qpq_content` | 118 | 题目访问、句子两种形态、评级门槛 |
| `qpq_adpcm` | 120 | IMA-ADPCM 流式解码 |
| `qpq_audio_index` | 106 | 音频 blob 的头与索引校验 |

不能上主机、因此刻意做薄的：`qpq_player`（贴着中断的音频输出）、`qpq_store`（NVS）、
`qpq_ui` 与四个页面。判断一段代码属于哪一边的规矩是：**如果它能被写成「参数的
函数」，它就属于主机那一侧。**

## 让两份实现从构造上就一致，然后证明它

音频 blob 由 Python 编码器产出、由 C 解码器播放。这两者一旦不一致，症状是一种几乎
无法归因的细微失真。所以生成器会产出一份固定向量 —— 一段 64 个样本的信号、Python
编码器为它编出的字节、以及 Python 解码器读回的序列 —— C 测试解码同一批字节，逐个
样本断言相等：

```c
for (uint32_t i = 0; i < QPQ_ADPCM_FIXTURE_SAMPLES; i++) {
    assert(s_bulk[i] == qpq_adpcm_fixture_expected[i]);
}
```

这是本仓库里最强的一条测试，因为它对边界的**两侧**都敏感。它已经抓出一个真缺陷：
C 的流式读取在打开时把游标放在了 1 而不是 0，于是每个片段都静默少发第一个样本。

这份固定向量同时也写明了**什么没有被保证**。它的后半段是满幅交替方波，在采样率上
接近奈奎斯特，ADPCM 本来就追不上；所以质量断言只覆盖前 48 个样本，那一段是衰减
正弦。对整段都断言一个误差上界，会是一句碰巧能过的谎话。

## 测拒绝路径，不只是测顺利路径

两种序列化格式都被刻意攻击，因为真正要命的失败发生在写到一半掉电的设备上，而不是
第一次运行时：

- **音频 blob 索引**有九条拒绝测试：空指针、头部被截断、索引被截断、魔数不符、
  版本不符、采样率不符、样本数为零、偏移跳过了一个片段、片段越出 blob、以及长度与
  索引推出的结尾不一致。
- **存档 blob**有六条：长度不符、魔数不符、版本不符、正文翻一位、已见位图翻一位、
  校验和被改坏。

两套都不仅断言「报了错」，还断言**调用方的结构体没有被改动**。第二条测试正是这样
抓出一个缺陷：`qpq_audio_index_open` 失败时提前返回而没有清空索引，于是忽略返回值的
调用方会继续拿着**上一次成功打开**的索引去寻址 —— 那种 bug 能跑，读到的却是别处。

## 测试要连真实数据，不是连一份副本

折行测试连了 `qpq_content` 与 `qpq_text`，走完整个题库、两种句子形态，断言没有一行
超出它那一层的预算：

```
ok  真实句子折行：最多 3 行（预算 3），单行最多 8 字（预算 8）
ok  答题页的槽位形态：最多 3 行、单行最多 8 字（预算 3 行 / 8 字）
```

如果测试是拿测试文件里抄一份内容来写的，它会在那份副本的行为上通过，而对应用什么
都没说。连上真实的表，才让「一屏放得下」从一句愿望变成一个可检查的事实 —— 也正是
它发现了两种句子形态之间的预算不一致。

同一个办法还浮出一个我写错的期望：一条六个字的句子被我断言会折成两行，但六个字一行
放得下，根本不会断。错的是测试，对的是代码；而这件事能被发现，唯一的原因就是测试
是拿现实去校验的。

## 让随机可复现

单局状态机里有全应用唯一的随机性，它用的是由调用方给种子的 xorshift32，而不是
`rand()`。固定种子产出固定抽题，于是「一局 20 题不重复」是测试**断言**的事实，而不是
它**指望**的概率。这也让「优先抽没见过的题」这条规则变得可测：把除了三道以外的题全部
标为已见，然后断言那三道一定出现。
