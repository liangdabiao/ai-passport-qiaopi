# 把经文整理成生成的 C 数组

为[三字经儿童学习游戏](sanzijing-kids-game/README.zh_CN.md)而写。这个应用的全部内容就是一篇一千二百字的启蒙经典。把这篇文字变成固件数据，做了三件事：**先统一用哪个版本**，**挑一种能让分歧暴露出来的文件格式**，以及**从它生成代码**，让 C 表、字符清单和字库子集永远不会各走各的。

## 问题在哪：经文本身就没有定本

《三字经》有多个长度不一的版本在流通。常见的通行本约 380 句、一千一百四十字左右；而扩充本还带着讲历代正史的段落。个别字在不同印本之间也有差异。

对一个识字应用来说，这不是学术问题。**一课的界面上显示了异体字，这个应用就在教异体字。** 所以经文必须刻意整理一遍，而且整理结果必须落成**唯一一个文件**，其它东西都从它派生。

把通行本和扩充本对完之后，差异分成两类，两类都得刻意定夺：

- **有 7 句只差一个字。** 每一句都按"与该段文意相符"的那个读法定稿，逐条列在下面。
- **有两个段落、共 24 句，通行本整段没有**：一段 8 句讲读史的顺序，一段 16 句讲最后几个朝代。两段都补了回来。

7 处订正逐条对照（左为通行本，右为定稿）：

| 通行本 | 定稿 | 说明 |
| --- | --- | --- |
| 名句读 | 明句读 | 同音致误；此处意为"明白句读"，非"有名的句读" |
| 乃孔伋 | 子思笔 | 通行本写人名，定稿写"笔"，与上文"诗既亡，春秋作"的句法一致 |
| 有荀杨 | 有荀扬 | 荀子、扬子；"扬"非"杨" |
| 王纲堕 | 王纲坠 | "坠"为坠落，此处指纲纪崩坏 |
| 应景命 | 膺景命 | "膺"为承受、担当 |
| 金满嬴 | 金满籝 | "籝"是竹箱，指"把书箱装满"，非姓氏"嬴" |
| 读史书 | 读史者 | 上句为"口而诵，心而惟"，对举应为"读史者" |

380 + 24 = 404 句，1212 字，565 个不重复的汉字。

重点不是"哪个版本才对"。重点是：这些差异是有限的、可枚举的、**一次就能定完**——前提是你把它们定在一个"其它一切由它生成"的文件里，而不是定在代码里。

## 一句一行，不加标点

定稿文件刻意做得很素：**每行恰好三个汉字，别的什么都没有。** 没有标点、没有行号、没有注释、没有元信息头。

```text
人之初
性本善
性相近
习相远
```

这个格式值得坚持，有四个理由：

- **行就是应用计数用的单位。** 一课是四行，一道题关于一行，一张认字卡是一行。让文件的单位和业务单位一致，就省掉了一整层解析。
- **diff 干净。** 评审者看到的是"某一行改了一个字"，而不是"一整段被重排了"。
- **没有语法可写错。** 不用引号、不用转义、没有可能与内容混淆的分隔符。
- **不加标点是有意为之，不是偷懒。** 原文就没有标点；加上去就等于改了应用要显示的内容。

## 生成 C 表，并且让常量从数据里算出来

`tools/sanzijing/gen_content.py` 读这个文件，写出 `main/szj_text.h` 与 `main/szj_text.c`。最值得照搬的一点是：头文件里的常量是**从数据算出来的**，不是手写的。

```c
#define SZJ_LINE_BYTES 10
#define SZJ_LINES_PER_STANZA 4
#define SZJ_LINE_COUNT 404
#define SZJ_STANZA_COUNT 101
#define SZJ_CJK_CHAR_COUNT 1212
```

手维护的计数，在有人追加一行的那一刻就错了，而它的失败方式是"某一课悄悄少了一句"。从数据推导之后，**往文本文件里加一行就是唯一需要做的改动**。

## 在生成器里校验，并且报出出错的行业号

只要文本不满足形状规则，生成器就拒绝产出任何东西，并且指明是哪一行坏了：

```python
for index, line in enumerate(lines):
    if len(line) != CHARS_PER_LINE:
        raise SystemExit(f"{TEXT}: line {index + 1} has {len(line)} characters, expected {CHARS_PER_LINE}")
    if not all("\u4e00" <= c <= "\u9fff" for c in line):
        raise SystemExit(f"{TEXT}: line {index + 1} has a non-CJK character: {line!r}")
if len(lines) % LINES_PER_STANZA != 0:
    raise SystemExit(f"{TEXT}: {len(lines)} lines is not a multiple of {LINES_PER_STANZA}")
```

三条规则，三个理由：

- **每行恰好三个字**——认字卡页面是按固定字节偏移切行的。出现一个四字行，它之后的所有田字格都会错位。
- **每个字符都是汉字**——混进一个标点或一个不可见字符，就会被当成一个格子，渲染出一个空白框。
- **行数是 4 的倍数**——否则最后一课会被截断。

报出行号这件事，比看上去更重要。"期望 3 个字符"而没有位置，意味着要靠手工二分查找一个 404 行的文件。

## 生成物必须声明自己是生成物

两份输出都以横幅注释开头，头文件里也再声明一次：

```c
// Generated by tools/sanzijing/gen_content.py from tools/sanzijing/sanzijing.txt.
// Do not edit by hand; run the generator instead.
```

`main/szj_text.c` 是 410 行字符串字面量，没人会去读它。没有这条横幅，它就是一个"顺手改一下"的头号目标——而那次改动会在下一次重新生成时被静默删掉。

## 用 `--check` 让 CI 抓住"忘了重新生成"

生成器支持 `--check`：把它**本该**写出的内容和仓库里已提交的做比较，不一致就失败，并且什么都不写。

```bash
python3 tools/sanzijing/gen_content.py --check
```

这就是把"记得重新生成"变成一条规则的东西。没有它，改了文本文件却忘了跑生成器，会产出一个**编译得过、但发布的是旧经文**的构建——最糟糕的一种失败，因为一切看起来都很健康。

## 把生成器按正确顺序串起来

两个生成器在设计上就是联动的。字库生成器的字符清单来源于同一个文本文件，于是链条是：

```text
sanzijing.txt
   ├─ gen_content.py  ->  main/szj_text.{c,h}       (数据)
   └─ gen_font.py     ->  assets/fonts/szj_font_*.c (字形)
```

所以往文本文件里加一行，可能也需要重新生成字库子集。**这是特性不是缺陷**：字符清单是经文与界面文案的并集，新出现的字会被自动收进去，而不是在某一课上变成一个空白框。两个都跑，再跑验证门。

## 把不变量测在能快速失败的地方

生成器在生成时校验文本。主机测试则**再验一遍生成出来的数据**，这样即使没人跑生成器，一份过期的提交也会被抓住：

```c
assert(SZJ_LINE_COUNT % SZJ_LINES_PER_STANZA == 0);
assert(SZJ_STANZA_COUNT * SZJ_LINES_PER_STANZA == SZJ_LINE_COUNT);
for (int i = 0; i + 1 < SZJ_LINE_COUNT; i++) {
    assert(strcmp(szj_line(i), szj_line(i + 1)) != 0);
}
for (int i = 0; i < SZJ_LINE_COUNT; i++) {
    assert(strlen(szj_line(i)) == 9);
}
```

后两条验的是**内容**而不是格式。连续两句文案相同，会让一道题有两个正确答案；长度不对的一句，会让田字格错位。两者都是对数据的检查，都在毫秒级跑完，而且**都不可能靠读代码发现**。

## 改完经文之后的操作顺序

```bash
# 1. 编辑 tools/sanzijing/sanzijing.txt(每行三个汉字)
python3 tools/sanzijing/gen_content.py          # 重新生成 C 表
python3 tools/sanzijing/gen_font.py             # 重新生成字库子集
python3 tools/sanzijing/gen_content.py --check  # 确认没有过期
python3 tools/sanzijing/gen_font.py --check
./tools/validate.sh --static                    # 数据不变量与主机测试
```

## 检查清单

- 有一个整理过的文件作为经文的唯一事实来源。
- 文件的单位与业务单位一致，且没有需要转义的语法。
- 生成器从数据推导每一个计数，而不是硬编码。
- 形状规则在生成时校验，并报出出错的行业号。
- 生成物带"请勿手改"的横幅，并指明是哪个生成器。
- 存在 `--check` 模式，让 CI 能抓到过期的输出。
- 读同一个源文件的生成器要一起重新生成。
- 数据不变量在主机测试里有断言，而不是只写在生成器里。
