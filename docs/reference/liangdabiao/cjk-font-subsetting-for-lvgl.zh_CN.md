# 为 LVGL 裁剪中文字库子集

做[侨批填字问答](qiaopi-quiz/README.zh_CN.md)（一个全离线中文日课设备）时攒下的经验。凡是界面上要显示中文的 AI Passport 应用都适用；下面所有数字都是在 8 MB Flash、无 PSRAM 的 ESP32-C3 上实测的。

## 为什么一定要裁子集

LVGL 自带 Montserrat，但它只有拉丁字母；另有一个默认关闭的思源黑体子集。把一个中文字符串设到字库不含该字的控件上，**不会报错**——标签只是不显示，或者画出一堆豆腐块。LVGL 没有字体回退链，所以**每一个显示中文的控件都必须显式指定一个含这些字的字库**。

这个应用只显示一章整理好的经文，加上它自己的界面文案，就已经需要 **1303 个不同的码点**。本项目三档子集把这一批全覆盖了。

## 字表要推导出来，不要手写

手维护的字符清单，在有人新增一个菜单文案的那一刻就过期了，而且失败是静默的。正确做法是把三个来源取并集，自动生成：

1. **章节源文件的全部字符**，并且要经过喂给 C 表生成器的**同一个模块**（`tools/qiaopi/content.py`）读取——这样 C 表和字库永远不会对「经文写了什么」各说各话。读取时要**先去掉所有空白再逐个取字符**；按空白切分会得到一句句语串而不是单个汉字，剪出来的子集里会一个汉字都没有。
2. **应用源码字符串字面量里的全部非 ASCII 字符**。扫描前先剥掉 `//` 与 `/* */` 注释，这样中文注释就不占 Flash；字符串字面量要原样保留，包括转义序列。生成出来的那两张 C 表要**显式排除**——它们的内容已经被章节源覆盖，再扫一遍纯属重复劳动。
3. **可打印 ASCII**（`0x20`–`0x7E`），以及界面自己会画出来的中文标点：`·，。！？、：；（）「」《》…—`。这些中文标点本来也会从经文里被捡进来，但把它们留在显式清单里，意味着某次章节编辑删掉一个标点，不会连带把字库悄悄裁小。

这样得到 1303 个码点：1079 个汉字，224 个来自另外两组。把它写进仓库里的 `charset.txt`，评审的人有东西可 diff，后来的人也能看出**某个字为什么在里面**：

```text
# total code points: 1303  (CJK 1079, other 224)

# --- CJK ideographs ---
一七万三上下不与两个之九了事二于五今从他以件任休众会住你保修偏停储儿先入全八六关...

# --- everything else ---
 !"#$%&'()*+,-./0123456789:;<=>?@ABC...·—…、。《》「」！（），：；？
```

（上面第一组汉字在这里为阅读方便截断了，真实文件里是 1079 个汉字**不分隔、连成一串**：分隔符本身会被转换器当成一个字形收进子集。第二组够短，一行读完，也是评审的人真正会看的地方。）

第二组的第一个字符是**空格**，它很容易丢：生成器里任何一步 trim 都会把 `U+0020` 去掉，清单悄悄变成 396 个——而且在有字符串真的需要空格之前，渲染一切正常，你根本不会发现。

## 转换之前先核对覆盖

这是性价比最高的一步：加载母字体的字符映射，把字表里每个码点都对一遍，有缺就直接让构建失败。

```python
from fontTools.ttLib import TTFont

font = TTFont(source_font, fontNumber=0, lazy=True)
cmap: set[int] = set()
for table in font["cmap"].tables:
    cmap |= set(table.cmap.keys())
missing = [c for c in chars if ord(c) not in cmap]
```

这一步之所以必要，是因为源文本会变。某一章引用了一个异体字或古字，就带进一个生僻码点；而把一个字体里没有的字交给转换器，它**不一定**会停——它可能照样产出一份缺这个字的字库，然后你要到真机上、在一行的中间，发现那里是一个空白方块。事先核对，就能把它变成一条构建错误，并把出错字符（最多 40 个）打出来。本项目这一步报的是 1303/1303 全部命中 Noto Sans CJK SC——代价只是遍历一遍字符映射，算很便宜的保险。

## 转换时把字符集当字面量字符串传进去

字表要作为一整个字面量字符串从 `--symbols` 传进去，而不是写区间。写区间会拖进成千上万个用不到的字，而裁剪的全部意义就是只为显示出来的字付钱。

```bash
lv_font_conv \
  --font NotoSansCJKsc-Regular.otf \
  --symbols "$(字表去掉注释后连成一串)" \
  --size 24 --bpp 4 \
  --format lvgl --no-compress \
  --lv-include lvgl.h \
  --lv-font-name qpq_font_24 \
  -o assets/fonts/qpq_font_24.c
```

几个值得说明的选择：

- **4 bpp。** 用 1 bpp 的话，16 px 的汉字会糊成一团——笔画根本表达不出来。4 bpp 是小字号还能看清的临界点；8 bpp 会让 Flash 翻倍，而在这块屏上肉眼看不出提升。
- **`--no-compress`。** 未压缩的点阵留在 Flash 里被内存映射直读，既不需要 `CONFIG_LV_USE_FONT_COMPRESSED`，也不需要解压缓冲。在没有 PSRAM 的芯片上，这个交易更划算。
- **锁死转换器版本。** 本项目用 `lv_font_conv` 1.5.3；生成数据的形状在不同版本之间会变，所以版本号写死在生成器里，而不是听凭 `PATH` 上是什么。
- **输出名带上字号**（`qpq_font_16`、`qpq_font_24`、`qpq_font_32`），这样控件的声明本身就说清了用的是哪一档。名字由尺寸循环推出来，两者不会走偏。

## 打开「大字体」格式

LVGL 默认文本格式字库里，每个字形的位图偏移量是用 16 位存的，点阵数据一旦超过 64 KB 就会溢出这个字段。这里点阵不压缩，所以体积是可以算出来的：1303 个字形、4 bpp，每个占 `字号 × 字号 ÷ 2` 字节。

| 档位 | 每个字形字节数 | 点阵总量 | 超出 64 KB 字段？ |
| --- | --- | --- | --- |
| 16 px | 128 | 50,816 | 否 |
| 24 px | 288 | 114,336 | 是 |
| 32 px | 512 | 203,264 | 是 |

三档里有两档溢出，所以这一项是必须的：

```text
CONFIG_LV_FONT_FMT_TXT_LARGE=y
```

它把这个偏移字段换成 32 位。不开的话，字库要么编不过，要么渲染出乱码——而且症状很有迷惑性，所以每当一份大尺寸生成字库行为异常，先查这个开关。注意这个开关是按字体**格式**生效的、不是按单个字体，所以 16 px 那一档也会跟着开——虽然它本来放得下。

## 搞清楚它到底花多少

在生成的源码上实测：

| 档位 | 生成的 C 源码 |
| --- | --- |
| 16 px | 293,734 字节 |
| 24 px | 565,633 字节 |
| 32 px | 920,969 字节 |
| **合计** | **1,780,336 字节（1.70 MB）** |

两条教训：

- **`.c` 文件体积不等于 Flash 占用。** 十六进制字面量大约每 1 字节点阵要花好几字节源码——这里三个文件合起来 1.70 MB 源码，对应的点阵其实只有约 368 KB，其余是字形描述符和字符映射表。照着目录列表估预算会差接近五倍，而且方向是「白白吓自己一跳」。
- **要按 `.rodata` 段做预算，不能只算点阵。** 一份生成字库放进 Flash 的不只是点阵，描述符和映射表都跟着进去。真正该看的数字是体积报告里的段大小。

点阵是 `const`，`.rodata` 从 Flash 直读，所以字库**不占 RAM**。这正是「未压缩 + 内存映射」在没有 PSRAM 的芯片上更划算的原因。

## 声明与使用

```c
LV_FONT_DECLARE(qpq_font_16);
LV_FONT_DECLARE(qpq_font_24);
LV_FONT_DECLARE(qpq_font_32);
```

三档在界面头文件里声明一次，然后给**每一个**文本控件设字体——包括那些先建成空、之后再填内容的。生成的源码文件要加一行注释说明「这是生成物、怎么重新生成」：它们大到没人会去读，又小到让人忍不住手改。

## 母字体不要进仓库

母字体 OTF 有 16 MB，不该待在一个固件仓库里。生成器并不需要它被提交：它先去一个配置好的路径找（环境变量 `QPQ_SOURCE_FONT`，默认指向仓库之外的一个目录）；找不到时，加 `--download` 才从固定 URL 拉取，并且**校验 SHA-256** 通过后才落盘，这样上游文件变了会直接报错，而不是悄悄改变渲染出来的字形。把字库名称、许可（SIL Open Font License 1.1）、锁定的哈希和转换器版本，连同生成文件一起记在 `assets/README.md` 里。

## 检查清单

- 字表由章节源、界面字符串字面量和符号清单三者推导而来，不是手写的。
- 扫描字面量前已剥掉注释，注释掉的中文不会被带进固件。
- 生成的 C 表被排除在扫描之外，文本只有一个事实来源。
- 每个码点都对着母字体的字符映射核过，缺一个字就构建失败。
- 任一份子集的点阵超过 64 KB 时，`CONFIG_LV_FONT_FMT_TXT_LARGE=y` 已打开——而且判断依据的那套算术是写下来的。
- 预算取自 map 文件或体积报告，而不是生成的源码文件大小。
- 母字体按固定 URL + 哈希下载，或直接从仓库外读取；不进仓库。
